# 交付前自检清单

> 每轮代码/配置/文档改动，交付前逐项确认。未通过的项不默认跳过，必须补齐或明确说明为何无法完成。

## A. 基础契约
- [ ] 是否读取并遵循了项目根 `AGENTS.md`？
- [ ] 工作区根与技术项目根是否区分清楚，未混用？
- [ ] `.coze` 存在且合法：`project_type` / `preview_enable` 已正确写入（不留空）、`sub_id` 合法且未改、`[subprojects].path` 与实际结构一致、`requires` 覆盖所需运行时？
- [ ] 涉及预览：`.preview` 已生成、`expose_port` 正确、加入 `.gitignore`、未 hardcode 端口、未碰系统保留端口？
- [ ] `AGENTS.md` 是否已更新（新模块/改核心逻辑/改运行方式/新长期约束）？

## B. 验证
- [ ] 已执行本次任务最相关的验证（类型检查 / lint / 构建 / 测试 / 探活 / 走通主路径）？
- [ ] 涉及可见界面或交互，是否在预览/运行时实际走通主路径？
- [ ] 部署配置已按部署 skill 确认？项目支持部署的 `[deploy]` 已配置或校验？
- [ ] 无法验证的部分，是否已如实说明缺口、原因与风险？

## C. 无副作用
- [ ] 未夹带无关改动（防目标漂移）？
- [ ] 无未说明的副作用？
- [ ] 变更是否为最小必要改动？
