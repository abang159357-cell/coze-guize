# 开发通用规则

> 跨项目复用的通用研发协作规范仓库。任何新项目开工时，把它沉淀进该项目的 `AGENTS.md`，即可让 Agent 自动遵守"稳定、可信、可长期运营"的研发方式。

## 这是什么

一套**不绑定具体技术栈**的通用研发规则底座，来自长期实践 + 官方机制核实（详见 `_依据核实.md`），覆盖从需求到上线的完整链路。每个具体项目通过自己的 `AGENTS.md` 补充领域上下文，与本仓库规则配合生效。

## 项目生命周期一站走通（主线）

> **看这一张图走完全程**：每一步标明「看协议哪节 / 用哪份清单 / 产出什么」。「谁是负责人」遵循官方协作模式——计划与验收部署由人类（项目所有者）掌舵，中间开发由 AI 在 Agent 模式无人值守推进。

| 阶段 | 负责人 | 依据/清单 | 产出 |
|---|---|---|---|
| ① 立项定需求 | 人类 | README「这是什么」 | 明确的原始需求 |
| ② 计划定案 | 人类 + AI | 协议「协作模式」计划模式 | 计划文档（目标/范围/里程碑/验收/停止/授权边界），未定案不进入下一步 |
| ③ 无人值守开发 | AI | 协议「无人值守开发执行流程」+ §二自动推进 + §四自动测试 | 可部署产物 + 测试证据 + 交付包 |
| ④ 推送 + CI | AI | `推送与CI交接.md` | 逐 commit 推 GitHub、CI 绿 |
| ⑤ 交付自检 | AI | `交付前自检.md` | 每轮改动通过自检清单 |
| ⑥ 上线前评估 | AI + 人类 | `上线前评估.md` | 可验证的「是否可上线」结论 |
| ⑦ 部署上线 | **人类（所有者）** | 协议§十权限边界 + 部署 skill | 线上服务对外可见 |
| ⑧ 运营迭代 | 人类 + AI | 协议§六运营与合规 + AGENTS.md | 看数据定方向，回到②迭代 |

**关键认知**：③的终点是「**可部署上线状态**」——判据 = 阶段自检通过 + `交付前自检.md` 通过 +（web）`test_run` 与 CI 全绿 + `上线前评估.md` 结论可上线。判定达成后停下，把交付包交人类验收部署，AI 不替代上线闸门。

## 目录结构

```
coze-guize/
├── README.md                       # 本说明
├── _依据核实.md                    # 各规则的官方依据与来源（防自研猜想）
├── 通用研发协议.md                  # 核心规则（主文档，建议并入新项目 AGENTS.md）
├── 推送与CI交接.md                  # 推送 GitHub + 触发 CI + 构建期 env 坑（真实可操作交接）
├── templates/
│   └── AGENTS.md.template          # 可直接套用到新项目的 AGENTS.md 骨架
└── checklists/
    ├── 交付前自检.md                # 每轮改动交付前的强制自检清单
    └── 上线前评估.md                # 上线前项目评估 + 对抗测试清单（含功能/交互逐项验收，交付闸门总出口）
```

## 如何使用（每个新项目三步）

1. **初始化时并进 AGENTS.md**：把项目读者的首条指令设为"套用通用研发协议"，把 `通用研发协议.md` 的内容并进新项目根 `AGENTS.md` 的固定章节。协作按官方模式推进：**计划模式定方案 → AI 在 Agent 模式无人值守开发（可部署状态）→ 人类验收 → 由项目所有者执行部署上线**（总纲见协议「协作模式」小节）。
2. **开发中遵守**：按「自动推进规则」推进，每轮改动交付前按 `checklists/交付前自检.md` 自检，改动核心逻辑时给出测试证据。
3. **上线前收口**：按 `checklists/上线前评估.md` 逐项核对（含功能可用性与交互完整性验收），通过后才交付。

> 需要把改动推上 GitHub / 接通 CI 的项目，另读 **`推送与CI交接.md`**——含逐一 push 流程、CI 触发与节奏、pnpm 版本对齐、`NEXT_PUBLIC_` 构建期 env 坑（均为线上实测可照做的操作，非泛泛规则）。

## 关键要点（一句话）

- **阻断即停**：同一问题最多凭证据试 1–2 次，无新证据就停、转做并行工作、如实报告。
- **复查须有据**：验证基于实际探测（输出/日志/页面/测试），不靠"推测应该没问题"。
- **真接通非 Mock**：真实调用不用假数据冒充成功。
- **正确性 ≠ 能编译**：可见改动必须在预览/运行时实际走通再声称完成。
- **最小确认点**：只在产品决策/不可逆/需授权处停下问人，其余连续推进。
- **多项目落地入口是 AGENTS.md**（官方必读机制），本仓库是它的"规则源"。

## 适用说明

- 适用：Web / 小程序 / App / 后端 / 脚本 / 库 / 自动化任务等任何技术栈与项目形态。
- 不含：类型独有的开发细节（如 web 用 test_run、小程序用 coze CLI）——那些按对应类型 skill 执行，本仓库只收敛"通用"部分。
- 与平台硬约束（端口 5000、pnpm/uv、`.coze` 落点、`sub_id` 不可改）冲突时，以平台约束为准。
